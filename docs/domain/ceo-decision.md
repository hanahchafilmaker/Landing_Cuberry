# [대표님 확인용] 도메인 정리 — 결정할 것 3가지

작성 2026-10-14 · 담당자 요약 · 기술 용어 최소화

---

## 1. 지금 상황 한 줄

- `cuberry.kr` 에는 **기존 회사 소개 사이트**가, `cubeberry.ai` 에는 **영문 제품 사이트**가 **각각 따로 서비스 중**입니다.
- 새로 만든 큐브베리 랜딩은 지금 `hanahchafilmaker.github.io/Landing_Cuberry/` 에 있고, **공식 도메인으로 옮길 준비가 끝났습니다**.
- 두 도메인 모두 **AWS** 에서 관리되고 있고, **메일(구글 워크스페이스)** 이 같은 도메인에 연결되어 있습니다 → 메일 레코드는 건드리지 않습니다.

---

## 2. 결정 1 — `cuberry.kr` 은 이렇게 연결합니다 (확정·진행 중)

**새 랜딩을 `cuberry.kr` 로 옮기고, 기존 회사 사이트는 `old.cuberry.kr` 로 남깁니다.**

- 방문자가 `cuberry.kr` 을 열면 → **새 랜딩** (히어로·포트폴리오·팀·문의)
- 기존 사이트가 필요하면 → `old.cuberry.kr` 에서 그대로 (링크가 끊기지 않게 보존)
- `www.cuberry.kr` 은 자동으로 `cuberry.kr` 로 이동
- 이미지·문의 폼·어드민은 모두 새 랜딩 기준으로 동작(준비 완료)

> 기존 사이트를 **완전히 내려도** 된다면 알려주세요 — `old.cuberry.kr` 보존 단계를 빼고 더 빨리 끝낼 수 있습니다.

**언제 바뀌나요?** 서버(DNS) 담당자가 레코드를 바꾸는 순간입니다(작업 10분, 반영은 보통 수십 분).
바꾸기 전과 같은 하루에 저장소 변경을 함께 반영하므로, **방문자 입장에서는 새 랜딩이 뜨는 시점만 달라집니다.**

---

## 3. 결정 2 — `cubeberry.ai` 은 어떻게 할까요? (대표님 판단 필요)

지금 `cubeberry.ai` 은 **비어 있는 주소가 아니라 영문 사이트가 돌고 있습니다**(XCONDA·Art Director Pro·Director’s Cut·AI VirtualSet 소개).

| 안 | 내용 | 좋은 점 | 주의할 점 |
| --- | --- | --- | --- |
| **(a) 지금 그대로 유지** ← **추천** | 영문 제품 사이트는 그대로, 새 랜딩은 `cuberry.kr` 에서만 | 손댈 것이 없음. 영문 사이트가 이미 검색에 잡혀 있음 | 회사 소개가 두 곳에 나뉨 |
| **(b) 영문도 새 랜딩으로 통일** | `cubeberry.ai` 접속 시 `cuberry.kr/en/`(영문 랜딩)으로 자동 이동 | 회사 소개는 한 곳에서 관리. 검색 순위가 한 곳으로 모임 | 지금 `cubeberry.ai` 의 기존 영문 페이지·검색 노출이 정리됨 |
| **(c) 별도 영문 사이트로 계속 운영** | 지금처럼 영문 제품 사이트 유지 + 새 랜딩과 서로 링크 | 제품(XCONDA) 홍보에 집중 | 콘텐츠를 두 곳에서 관리, 같은 내용을 중복 게시하면 검색에 불리 |

**담당 의견**: **(a) 로 두고, 필요해지면 (b) 로 전환**하는 것이 안전합니다.
영문 랜딩(`cuberry.kr/en/`)은 이미 만들어 두었습니다(지금은 자동 이동 주소).
“영문도 새 사이트로 통일하자”로 정해지면 그때 `cubeberry.ai` 를 `cuberry.kr/en/` 로 넘기는 작업만 하면 됩니다(별도 견적·개발 불필요).

**되묻고 싶은 것**: `cubeberry.ai` 의 XCONDA 소개 페이지들은 **앞으로도 계속 운영**할 계획인가요?
(운영한다 → (a)/(c) / 새 사이트로 합친다 → (b))
